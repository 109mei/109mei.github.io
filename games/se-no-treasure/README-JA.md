# せーの！おたから

こっそり島を選んで、せーので公開する2人用のブラウザゲームです。1試合8ラウンド、目安は約3分。

## あそぶ方法

### スマホ2台でオンライン

1. ふたりとも同じゲームページを開きます。
2. ひとりが「スマホ2台で あそぶ」→「新しい部屋をつくる」を押します。
3. 表示された**8文字の部屋コード**、または「招待リンクをコピー」で取得したリンクを相手に送ります。
4. 相手は「スマホ2台で あそぶ」からコードを入力し、「コードで部屋に入る」を押します。招待リンクから開いた場合も、ホームから操作を始めます。自動では接続されません。
5. 接続できたら、ふたりとも「準備OK！」を押して開始します。
6. 島と探し方を選び、「この島に決めた！」で確定します。ふたりの選択がそろうと結果が出ます。
7. 試合後、ふたりとも「もう一度、せーの！」を選ぶと、新しい試合を始められます。

部屋コードは、知っている相手にだけ共有してください。通信中はページを開いたままにしてください。

### 1台を交代で使う

「1台で 交代してあそぶ」を選びます。ネコ船長が選んだ後は、選択を隠した受け渡し画面になります。キツネ船長にスマホを渡し、「受け取った！ 島を選ぶ」を押してください。相手の選択中は画面を見ないで遊びましょう。

### ひとりで練習

「ひとりで練習」でCPUと対戦できます。CPUは公開されている試合情報を使い、人間が選んだ島は参照しません。

## ルール

- 3つの島のおたからは、2枚・3枚・5枚。配置はラウンドごとに変わります。
- ふたりが違う島を選んだ場合、それぞれその島のコインを獲得します。
- 同じ島を選んだ場合、ふつうに探した人は0枚です。
- 「よくばる」は1試合に2回まで使えます。
  - 違う島なら、その島のおたからに**さらに3枚**追加。
  - 同じ島なら、**2枚失います**。持ちコインは0枚未満にはなりません。
- 8ラウンド後、コインが多い船長の勝ち。同じ枚数なら引き分けです。

## 通信・料金について

- ゲームに購入、課金、広告、アカウント登録の機能はありません。
- オンラインでは無料のPeerJS接続サービスを使い、接続後はWebRTCで対戦相手と通信します。接続に必要なネットワーク情報は、接続サービスや対戦相手に伝わります。
- STUNだけを設定しています。**有料のTURN中継サーバーや従量課金APIは利用していません。**
- そのため、学校・会社のネットワーク、厳しいNATやファイアウォール、携帯回線の組み合わせなどによっては接続できません。別の通信環境や1台交代モードを試してください。無料接続サービスの稼働や接続成功は保証できません。
- 端末・通信会社による通常のデータ通信料は別途発生する場合があります。
- 切断した試合に、切断を理由とする勝利は与えません。再接続して途中から復帰する機能はなく、新しく部屋を作り直します。
- ページ読み込みだけではPeerJSへの接続を始めません。「新しい部屋をつくる」または「コードで部屋に入る」の操作後に開始します。

## 公平性とプライバシー

オンラインの選択は、最初にSHA-256のコミットメントを交換し、ふたりが選択を固定してから公開します。試合ID・ラウンド・プレイヤー番号・安全な乱数をハッシュに含め、後出しや相手のコミットメントのコピーを検出します。両端末で同じルールを計算し、各ラウンドのコイン数と残り使用回数の一致を確認します。

これは本人確認や第三者による大会運営システムではありません。部屋コードを知った相手の身元を確認する機能はありません。

サウンドと動きの設定は、ブラウザのローカルストレージに保存します。

## 表示・操作

- 縦持ちスマホを中心に設計しています。
- ボタンの操作領域は48px以上を基本にしています。
- サウンドは初期状態ではOFFです。スピーカーボタンまたは設定から切り替えられます。
- 設定の「動きをひかえめに」と、端末の視差効果を減らす設定に対応しています。
- 演出の終了を待たないとゲーム処理が進まない構造にはしていません。

## 開発・ローカル確認

ビルド不要の静的HTML/CSS/ES Modulesです。外部フォントや画像生成API、購入アセットは使っていません。イラストはコードで作成したSVGです。

HTTPS、またはlocalhostで開いてください。コミットメントと安全な乱数にはWebCryptoを使用します。HTMLファイルを直接開くのではなく、静的HTTPサーバーを使用してください。

例：

```sh
python3 -m http.server 8765
```

ブラウザで `http://localhost:8765/` を開きます。

テスト：

```sh
node --test engine/*.test.mjs transport/*.test.mjs tests/*.test.mjs
```

PeerJS 1.5.5はローカル同梱しています。ライセンスは `vendor/peerjs-LICENSE`、出典とハッシュは `vendor/peerjs-provenance.json` にあります。

## 検証範囲

自動テストでは、ルールの独立した計算との照合、入力検証、状態の不変性、コミットメントのプレイヤー束縛、1台交代、CPUの全8ラウンド、二重確定の防止、切断、遅延したSHA検証、模擬回線上の実際のRoomTransportを使った3試合・再戦を確認しています。

これらの模擬通信テストは、実際のインターネットでの接続成功を証明するものではありません。ブラウザでの画面・操作確認と、物理的に異なるスマホ2台での実回線接続確認は別の検証です。**本README作成時点では、実機iPhone/Android2台での対戦は未検証です。** 実機対応を確認済みとする記載はしていません。

### ブラウザでの追加確認（2026年10月11日）

クラウド上の実ブラウザで、390×844と360×640の画面表示、CPU戦の全8ラウンドと再戦、1台交代モードの受け渡し時の選択非表示、ラウンド結果（5対2）、SVGのサウンドボタン表示を確認しました。これは物理スマートフォンの実機確認ではありません。

オンラインでは実際のPeerJSサービスで部屋を作成できましたが、同ブラウザ環境の2クライアント間のWebRTC接続は成立しませんでした。ローカル候補は双方で得られたものの、リモート候補・候補ペアは得られていません。原因は確定しておらず、**実回線でのオンライン対戦は動作確認未完了です。オンラインはテスト版として表示しています。** 接続できない場合は「1台で交代してあそぶ」を利用してください。
